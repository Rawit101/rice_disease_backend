# ชุดข้อมูลเพิ่มเติมสำหรับโมเดลโรคข้าว

อ่าน `report.json` เพื่อดูจำนวนจริง ชุดนี้ประมวลผลรูปต้นทางครบ 2,817 ไฟล์ แต่ไม่ได้มี label ที่ยืนยันถูกต้องครบทุกภาพ

- `images/pool/` เก็บรูปครบทุกไฟล์ต้นทาง โดยแปลงสำเนาเป็น JPEG และไม่แก้ต้นฉบับ
- `train.txt`, `val.txt`, `labels/pool/` คือชุดที่ส่งเข้า YOLO Segmentation ได้
- `data.yaml` มีหมายเลข 0–8 ตรงกับโมเดลเก่า ไม่มีการเพิ่ม Healthy เป็นโรคที่ 10
- `weights/best.pt` คือสำเนาโมเดลเก่า ไม่ได้เทรนหรือเปลี่ยนน้ำหนัก
- `manifest.json` บอกที่มา สถานะ คุณภาพ annotation กลุ่มรูปซ้ำ และเหตุผลรายภาพ
- `excluded.csv` คือภาพที่ยังใช้เทรนไม่ได้ ไม่ถูกแทนด้วย label ว่าง
- `review/` เก็บผลร่างและขอบเขตวัตถุที่ยังไม่ยืนยัน เพื่อใช้แก้ต่อ ห้ามนำทั้งโฟลเดอร์นี้เข้าเทรนเป็นโรคโดยตรง

## คุณภาพของ label

`ai_visually_screened` = AI ตรวจตำแหน่งและความครบของขอบเขตจากภาพแล้ว ชื่อโรคอิงโฟลเดอร์ต้นทาง ไม่ใช่การรับรองโดยนักโรคพืช

`ai_visually_screened_background` = ภาพจากโฟลเดอร์ healthy ที่ AI ดูแล้วไม่เห็นเป้าหมายของ 9 โรคเดิมอย่างชัดเจน ใช้ label ว่างเป็นภาพพื้นหลัง ภาพที่กำกวมหรือสีผิดปกติถูกพักไว้ ไม่ใช่การรับรองว่าต้นข้าวปราศจากทุกโรค

`two_model_pseudo_label` = โมเดลสองรุ่นทำนายคลาสตรงกับโฟลเดอร์ จำนวนวัตถุเท่ากัน คะแนนแต่ละวัตถุอย่างน้อย 0.5 และขอบเขตแต่ละคู่ IoU อย่างน้อย 0.5 ยังเป็น label อัตโนมัติที่ผิดหรือตกหล่นได้ โมเดลทั้งสองอาจมีข้อมูล/ข้อผิดพลาดร่วมกัน ความเห็นตรงกันไม่ได้รับรองความถูกต้อง

ดู `has_unreviewed_pseudo_labels` ใน report ว่ารอบนี้มี pseudo-label ผ่านเกณฑ์หรือไม่ ชุด validation ใช้ตรวจการทำงานและเปรียบเทียบกับ annotation ได้ แต่ใช้ยืนยันความแม่นยำโรคจริงไม่ได้ `data_checked_val.yaml` ถ้ามี จะประเมินเฉพาะภาพ validation ที่ AI ตรวจแล้ว ซึ่งมีคลาสจำกัดและยังไม่ใช่ชุดทดสอบอิสระ

การคัดออกครอบคลุมรูปซ้ำที่ชื่อโรคขัดกัน โรคใหม่ที่โมเดลยังไม่รู้จัก ภาพ healthy ที่ยังกำกวม ขอบเขตที่ตรวจแล้วพบปัญหา และผลสองโมเดลที่ไม่ตรงกัน ไม่มีการเปลี่ยนชื่อผลทำนายให้ตรงโฟลเดอร์โดยอัตโนมัติ ไม่มีการใช้หน้ากากวัตถุทั่วไปแทนรอยโรค

## ส่งให้เพื่อน

ส่ง ZIP ทั้งไฟล์ แตกแล้วเปิดโฟลเดอร์ที่มี README นี้ ใช้ Python 3.10 ขึ้นไป ติดตั้ง:

```bash
python -m pip install -r requirements.txt
python handoff_validate.py --load-images
```

## ทางเลือกที่เหมาะสำหรับเพิ่มความสามารถโมเดลเก่า

ชุดที่ผ่านเกณฑ์รอบนี้มีภาพโรคเพียงบางคลาสและมีภาพพื้นหลังจำนวนมาก จึงจัดเป็นข้อมูลเพิ่มเติมสำหรับรวมกับชุดเดิม ไม่ควรใช้ชุดเล็กนี้แทนข้อมูลเดิมทั้งหมด ให้นำชุดเทรนเดิมที่มี label ถูกต้องมาร่วมด้วย ตัวช่วยนี้รวมภาพเพิ่มเฉพาะฝั่ง train และใช้ val/test เดิม:

```bash
python merge_rice_training.py --original-yaml /path/to/original/data.yaml
yolo segment train model=weights/best.pt data=merged_with_original/data.yaml imgsz=800 epochs=50 batch=4 device=0
```

ตัวช่วยจะตรวจชื่อและลำดับคลาสเดิม รวมถึงกันภาพเพิ่มที่ตรวจพบว่าซ้ำหรือคล้าย val/test เดิม ไม่มีชุดข้อมูลเดิมในแพ็กนี้ จึงยังไม่ได้รันการรวมจริง

คำสั่งเทรนเป็นตัวอย่างสำหรับ GPU NVIDIA ให้ผู้เทรนเลือก batch/epochs ตามเครื่องและผล validation อย่าใช้ `resume=True` เพื่อเพิ่มรูปหรือเปลี่ยนชุดข้อมูล และอย่านำผลเทรนใหม่ไปทับไฟล์โมเดลใช้งานจนกว่าจะเปรียบเทียบกับชุดทดสอบเดิม

รูปซ้ำแบบไฟล์เดียวกัน และภาพใกล้เคียงที่ตรวจพบจากการพลิก/หมุน จะอยู่ฝั่งเดียวกัน แต่ยังรับรองความเป็นอิสระระดับแปลงนา/ช่างภาพไม่ได้ เพราะไม่มีข้อมูลการเก็บภาพ

## งานที่ยังต้องทำก่อนใช้รูปทั้งหมด

โรคถอดฝักดาบและรากปมต้องมี annotation ที่ระบุส่วนเป้าหมายจริงก่อนเพิ่มคลาส ทั้งสองโรคยังไม่ได้ถูกรวมเป็น label โรคในชุดเทรนนี้ ภาพ healthy ที่ยังพักไว้ต้องตรวจเพิ่ม ภาพที่มีป้ายโรคขัดกันต้องแก้ชื่อให้ถูกต้องก่อน

archive.zip ชุดเพิ่มเติมจาก Drive ยังไม่รวมในจำนวน 2,817 ภาพ ต้องดาวน์โหลดและแตกเสร็จก่อนจึงจะประมวลผลต่อได้

การตรวจรูปแบบไฟล์ผ่านหมายถึง YOLO โหลดข้อมูลได้ ไม่ได้หมายความว่าทุก label ถูกต้องหรือการเทรนจะทำให้โมเดลดีขึ้นโดยอัตโนมัติ
